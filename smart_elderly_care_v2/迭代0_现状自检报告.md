## 三、核心问题诊断（⚠️ 重点关注）

### 3.1 评估结果：虚假的 100%

```
整体指标:
  准确率 (Accuracy): 1.0000
  精确率 / 召回率 / F1 (Macro): 1.0000 / 1.0000 / 1.0000
  AUC (Macro): 1.0000

混淆矩阵:
[[360   0   0]
 [  0  93   0]
 [  0   0  47]]
```

**这个 100% 是假的，不可作为项目指标。** 原因：

1. **训练数据与测试数据同源同分布**：都由 [`prepare_data.py`](smart_elderly_care_v2/data/prepare_data.py:243) 的 `_generate_video_features` 等函数生成，本质是 `np.random.randn` + 维度偏置。
2. **标签由规则硬编码**，特征里直接嵌了"答案线索"。例如跌倒样本：
   ```python
   base_features[256:512] += 1.0          # 跌倒特征增强
   base_features[512:768] += stillness/100
   ```
   模型只需学会"看 256~512 维有没有偏置"就能猜对标签——这是 **捷径学习 (shortcut learning)**，不是语义理解。
3. **encoder 是摆设**：[`encoders.py`](smart_elderly_care_v2/models/encoders.py:1) 里的 VideoEncoder（吃 [B,3,16,224,224] 原始视频）从未被调用；[`dataset.py`](smart_elderly_care_v2/models/dataset.py:26) 直接 load 768 维"已提取"向量。所谓多模态融合，实际融合的是 4 段随机噪声。

**结论**：当前模型在真实视频/音频上几乎必然失效。这正是迭代1（真实特征）+ 迭代2（重训）要解决的核心。

### 3.2 App 侧特征提取同样不可靠
[`feature_extractor.py`](smart_elderly_care_app/inference/feature_extractor.py:18) 的 `VideoFeatureExtractor` 用灰度直方图 + 随机噪声投影到 768 维，与训练时的"维度偏置"分布完全不一致 → 即使模型训好，App 线上特征也对不上。

### 3.3 图表中文乱码
`confusion_matrix.png` / `per_class_metrics.png` 中文标签显示为方块（DejaVu Sans 缺 CJK 字形）。**功能正常，美观问题**，留待迭代3统一修中文字体。
