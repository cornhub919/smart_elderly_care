### 0.3 五个致命硬伤（必须在交付前解决，否则答辩翻车）

**硬伤 1：编码器与训练数据脱节（最严重）**
- [`encoders.py`](../smart_elderly_care_v2/models/encoders.py:12) 里 `VideoEncoder` 接收 `[B,3,16,224,224]` 原始视频、`AudioEncoder` 接收 Mel 频谱。
- 但 [`dataset.py`](../smart_elderly_care_v2/models/dataset.py:26) 加载的是 `video_features.npy`（768 维**已提取**向量），[`fusion_net.py`](../smart_elderly_care_v2/models/fusion_net.py:179) 的 `forward` 入参也是 768 维向量。
- 也就是说：**`encoders.py` 在训练/推理中从未被调用**，纯属摆设。README 里"VideoMAE + AST"是画饼。

**硬伤 2：训练数据是带标签的随机噪声**
- [`prepare_data.py`](../smart_elderly_care_v2/data/prepare_data.py:249) 生成特征的方式是 `np.random.randn(768)*0.1`，再按风险等级往某些维度区间**加常数偏置**（如跌倒往 `[256:512]` 加 1.0）。
- 模型学到的是"第几段维度有偏置→标签"的捷径，**不是真实多模态语义**。一旦换成真实特征，模型必然失效。

**硬伤 3：App 端到端是假的**
- [`feature_extractor.py`](../smart_elderly_care_app/inference/feature_extractor.py:96) 视频特征用 cv2 灰度直方图 + **`np.random.randn*0.1` 填充**；音频用 MFCC + 随机噪声。
- 用户上传真实视频/音频后，提取出的特征与模型训练时见过的"偏置噪声"分布完全不同 → 演示时大概率输出错误或无意义结果。

**硬伤 4：模型代码重复定义，极易不一致**
- [`predictor.py`](../smart_elderly_care_app/inference/predictor.py:59) 把 `MultiModalFusionNet` 整个抄了一遍，而不是 import V2 的。两份代码一旦改动不同步，权重就加载失败。

**硬伤 5：缺少交付级产出物**
- 无实验报告/论文、无评估图表（`evaluate.py` 跑不起来）、无演示视频、`rebuttal_plan.md` 的待办未完成。

### 0.4 已有可复用资产（别推倒重来）

## 第一部分：交付目标定义

### 1.1 什么叫"可观、可交付"

一个能在答辩现场**经得起追问**的多模态大作业，需同时具备：

1. **真实闭环**：上传一段真实视频/音频 + 输入生理/用药数据 → 系统给出风险等级，且每个模态有**可解释的中间结果**（不是黑盒乱抛概率）。
2. **有学习的融合**：存在一个训练过的融合模型，有训练曲线、有测试集指标、有混淆矩阵，并与规则 baseline 做对比。
3. **数据诚实**：清楚说明数据来源（公开数据集 + 模拟），不假装有海量真实跌倒数据。
4. **完整文档**：技术报告（含架构图、实验、消融、局限）、使用说明、演示视频。
5. **可复现**：`README` 里一条命令跑通 demo，一条命令跑通评估。

### 1.2 范围裁剪（防止做不完）

- **做**：视频跌倒、音频异常、生理异常、用药依从、四模态融合、周报生成、Streamlit 演示、技术报告。
- **不做**：实时摄像头流（用上传代替）、真实手环硬件接入（用模拟时序）、医生端接口、多用户系统。

### 迭代 1：把"伪编码器"变成"真单模态分析 → 特征"（2~3 天）⭐核心

**目标**：让每个模态的输入是真实的，特征是真实有语义的，而不是随机噪声。

**思路**：不追求端到端可微（VideoMAE 太重），而是采用方案 PDF 推荐的 **"单模态真实分析器 + 学习型融合"** 架构：

```
真实视频 → V1 MediaPipe 跌倒检测器 → 跌倒置信度/姿态特征向量(768维)
真实音频 → librosa + 轻量CNN/YAMNet → 音频事件特征(768维)
生理数据 → 阈值+IsolationForest → 异常分数+统计特征(256维)
用药数据 → 规则 → 依从率/漏服特征(128维)
          ↓ （以上都是真实、可解释的）
   V2 Cross-Attention 融合网络 → 风险等级
```

**任务**：
1. **视频模态真实化**：在 App 的 `feature_extractor.py` 里，用 V1 的 [`FallDetector`](../smart_elderly_care/modules/video/fall_detector.py:25) 跑真实视频，输出 `{fall_confidence, center_height_drop, body_angle, stillness_duration, motion_level}` 等真实特征，再用一个固定投影（或学习的小 MLP）扩到 768 维。**特征来源是真实姿态，不是直方图+噪声**。
2. **音频模态真实化**：保留 librosa MFCC/Mel，但**去掉随机噪声填充**，改用真实声学特征（过零率、谱质心、频谱通量、能量包络）+ 可选接入预训练 YAMNet/PANNs 提取 embedding（HuggingFace 上有轻量版）。
3. **生理模态真实化**：[`HealthFeatureExtractor`](../smart_elderly_care_app/inference/feature_extractor.py:210) 改为输出真实统计量（均值/方差/极值/异常计数/Z-score），不再 `np.tile` 随机填充。
4. **用药模态**：已经是规则的，只需把"应服/已服/漏服/依从率"编码成稳定的 128 维（one-hot 桶 + 数值，不是随机）。

**出口标准**：对同一段真实跌倒视频，视频特征在"跌倒维度"上有显著响应（可打印出数值验证）；不同输入产生不同且合理的结果。

**难点与对策**（见第三部分详解）：
- 难点 A：MediaPipe 在弱光/遮挡下关键点丢失 → 对策：缺失帧用上一帧插值 + 置信度门控。
- 难点 B：真实特征维度与模型训练分布不匹配 → 这是迭代 2 要解决的数据重建问题。

### 迭代 2：重建训练数据 + 重训融合网络（2 天）⭐核心

**目标**：让模型学的是**真实特征空间**里的模式，而不是随机噪声偏置。

**关键决策**：不追求"海量真实跌倒数据"（不现实），而是构建**半合成数据集**，并诚实标注。

**任务**：
1. **构建真实特征语料库**：
   - 视频：用 UR Fall Detection 数据集（公开，约 70 跌倒 + 40 ADL）跑迭代 1 的真实特征提取器，得到真实的"跌倒特征向量"和"正常特征向量"。
   - 音频：用 ESC-50 / 自录少量撞击声/呼救声，提取真实音频特征。
   - 生理：基于医学正常范围 + 异常范围，生成带时间结构的时序（比纯 random 合理得多）。
2. **重写 [`prepare_data.py`](../smart_elderly_care_v2/data/prepare_data.py:22)**：
   - 不再 `np.random.randn`。改为：从真实特征语料库**采样**真实特征原型，再按场景规则做混合/扰动（如跌倒 = 真实跌倒视频特征 + 真实撞击音频特征 + 异常生理特征）。
   - 生成 5000~10000 样本，**持久化**到 `data/processed/train|val|test/`。
3. **重训**：用现有 [`train.py`](../smart_elderly_care_v2/train.py:29) 训练，开启 TensorBoard，保存训练曲线。
4. **跑 [`evaluate.py`](../smart_elderly_care_v2/evaluate.py:28)**：产出混淆矩阵、各类别 P/R/F1、AUC，保存到 `eval_results/`。
5. **消融实验**：训练 (a) 全模态 (b) 去掉视频 (c) 去掉音频 (d) 用 V1 规则融合 baseline，对比指标。**这是答辩加分项**。

**出口标准**：测试集准确率有意义（>随机基线），消融表能说明"多模态比单模态好"，训练曲线图存在。

**难点与对策**：
- 难点 C：UR Fall Detection 数据集下载/格式处理 → 对策见第三部分。
- 难点 D：真实特征数量少，模型过拟合 → 对策：特征级数据增强（加噪、混合、Mixup），见第三部分。

## 第三部分：难点专项攻关（不好实现的部分怎么完成）

### 难点 A：MediaPipe 姿态在真实居家视频中不稳定

**问题**：弱光、侧身、遮挡时关键点缺失，跌倒检测误报/漏报。

**对策（分三层）**：
1. **帧级**：关键点 `visibility < 0.5` 的帧，用上一帧关键点线性插值；连续缺失 >1 秒则标记"视频质量不足"，降级该模态权重。
2. **时序级**：不靠单帧判断，用滑动窗口（如 1.5s）内的重心高度变化率 + 躯干角度方差做判断（[`fall_detector.py`](../smart_elderly_care/modules/video/fall_detector.py:25) 已有历史记录机制，需调参）。
3. **兜底**：关键点完全丢失时，退回"运动幅度"特征（帧差法光流），仍能粗判跌倒。
**实现成本**：低，V1 代码已具备基础，主要是加插值和置信度门控。

### 难点 B：真实提取的特征维度/分布与模型不匹配

**问题**：迭代 1 的真实特征是 5~50 维统计量，模型要 768 维；直接补零或随机填充会破坏语义。

**对策**：
1. **阶段 1（保底）**：用一个**固定的可解释投影**把真实低维特征扩到目标维（如把 [fall_conf, angle, motion] 重复 + 位置编码 + 归一化），保证数值稳定。先让 demo 跑通。
2. **阶段 2（迭代 2 重训后）**：重新训练时，融合网络的第一层投影会自动学到"如何从这种特征空间映射"，此时真实特征与模型已对齐。
3. **关键**：训练数据和推理数据**用同一套特征提取器**（这是当前项目最大的 bug —— 训练用 random，推理用 cv2，两边不一致）。统一到一个 `FeatureExtractor` 类即可根治。

### 难点 C：公开数据集获取与对齐

**问题**：UR Fall Detection、ESC-50 需下载、解压、格式不一。

**对策**：
1. **视频**：UR Fall Detection（http://fenix.univiz.pt/homepage/1 → 实际 GitHub 有镜像）约 1.5GB，含 `falls/` 和 `adls/`。写 `download_dataset.py` 自动下载解压。
2. **音频**：ESC-50（约 600MB，50 类环境声）够用；或用 `torchvision`-style 的 `urbansound8k` 子集。挑选"crash/glass_break/scream"等类。
3. **对齐**：每个数据集写一个 `to_features.py`，统一输出 `[N, 768]` 的 `.npy`，供 `prepare_data.py` 采样。
4. **降级方案**：若网络不通，用自录 20 段手机视频（跌倒模拟 + 正常活动）+ 公开音频子集，量少但真实，答辩时说明"受限于数据规模，采用小样本 + 数据增强"。

### 难点 D：真实特征数量少导致过拟合

**问题**：UR Fall Detection 只有约 110 段视频，提取后特征样本极少。

**对策（特征级增强，不依赖原始视频）**：
1. **加噪**：真实特征 + 高斯噪声（σ=0.05~0.15）生成新样本。
2. **Mixup**：跌倒特征 ⊕ 正常特征 按比例 α 混合，标签软化为 (α, 1-α)。
3. **场景组合**：跌倒视频特征 × 多种音频特征 × 多种生理特征，组合爆炸扩充（这正是多模态的优势 —— 单模态样本少，但组合后量大）。
4. **正则**：训练时加大 dropout（已配 0.2/0.3）、weight_decay、早停（已配 patience=10）。
**理论支撑**：多模态组合增强在医疗低频事件场景有文献支持，可写入报告。

### 难点 E：模型代码两处定义不一致导致权重加载失败

**问题**：[`predictor.py`](../smart_elderly_care_app/inference/predictor.py:59) 与 [`fusion_net.py`](../smart_elderly_care_v2/models/fusion_net.py:74) 各有一份 `MultiModalFusionNet`。

**对策**：
